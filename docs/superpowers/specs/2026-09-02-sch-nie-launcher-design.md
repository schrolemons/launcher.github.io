# SCH-NIE 项目启动器设计

## 目标

将当前 Astro 站点的根页面改造为一个面向桌面设备的项目启动器，用统一界面聚合 `ark.sch-nie.com`、`blog.sch-nie.com`、`zero.sch-nie.com` 和 `world.sch-nie.com`。

启动器只负责展示项目预览、项目资讯与外部入口，不嵌入或复刻各项目的专属站内页面。用户在左侧选择项目后，启动器切换对应的背景、说明、资讯与视觉主题；只有点击右下角的项目专属主按钮时，才在新标签页打开对应项目网站。

## 设计原则

- 以用户提供的鹰角启动器截图作为布局与氛围参考，不复制其商标、账号系统或桌面客户端专属功能。
- 默认优先展示 ARK，并复用现有 HLS 首页视频作为静音自动播放背景。
- 项目信息、资讯、按钮文案、背景媒体和工具入口全部通过单一配置模块维护。
- 四个主项目拥有彼此独立的主按钮文案，不使用统一的“连接网页”。
- 第一阶段仅支持桌面端；移动端显示品牌化拦截提示，不初始化视频、轮播或启动器主体。
- 保留现有非首页源码，避免无关的不可逆清理，但不在新首页暴露旧导航和旧栏目入口。

## 视觉结构

页面使用单屏启动器构图，不产生正文滚动。

1. 页面底层显示当前项目背景的模糊放大版本，并叠加暗色遮罩。
2. 主启动器窗口位于视口中央，具有安全边距、圆角边框、半透明玻璃层和柔和阴影。
3. 左侧深色项目轨道顶部显示 SCHNIE 标识，中部依次显示 ARK、BLOG、ZERO、WORLD 项目按钮，底部显示项目总览按钮。ARK 排在首位并默认选中。
4. 中央背景舞台铺满当前项目的图片、MP4 或 HLS 视频，并叠加暗角、底部渐变和项目文字标识。
5. 底部资讯坞左侧显示当前轮播封面，右侧显示“公告 / 新闻 / 资讯”标签与内容列表。
6. 右侧工具轨道显示 Monitor、GitHub、微信公众号等可配置入口。
7. 右上控制区显示当前项目域名，并提供声音、背景播放和全屏控制。
8. 右下主按钮使用当前项目强调色和独立文案；旁边的圆形按钮展开简短项目详情。

项目切换使用约 400 毫秒的淡出、轻微位移和强调色过渡。背景是视频时，仅当前项目的视频保持播放。系统启用 `prefers-reduced-motion` 时取消非必要动画。

## 商业化视觉修正基准

2026-09-03 的桌面验收以用户提供的两张鹰角启动器截图为氛围和比例参考，并以以下可验证约束替代早期的紧凑原型布局：

- 主窗口在常见桌面视口使用 24–32 像素安全边距，宽高随视口扩展，不再受 `84rem` 宽度或 `48rem` 高度限制；窗口在 `1920x1080` 下应接近铺满屏幕，在 `1440x900` 和 `1366x768` 下仍保持完整且不产生页面滚动。
- 窗口形成稳定的三段式视觉层级：左侧项目轨、中央媒体舞台、贴近舞台右缘的窄工具轨。主内容内部再分为顶部控制区、中央项目识别区和底部信息/行动区，各区不得依赖内容高度互相挤压。
- 背景图片、海报和视频统一填满媒体舞台，使用 `object-fit: cover`；每个项目可通过 `media.position` 配置视觉焦点。舞台在明暗素材上都保留一致的暗角、底部可读性渐变和轻微环境色，不拉伸、不显示空白边。
- 信息坞使用固定外框、固定封面比例和固定内容窗高度。“公告 / 新闻 / 资讯”切换只替换内容，不改变信息坞的尺寸或位置；超出可见行数的内容在窗内裁切，不推动主按钮、项目名称或其他组件。
- 右侧工具轨使用统一尺寸的图标按钮、分组留白、悬停提示和选中态；可扫码工具仍打开二维码弹层，可直接访问工具仍使用安全的新标签页链接。工具名称不再以粗糙的常驻文字胶囊挤占背景。
- 左上角显示完整的自有品牌标识 `SCHNIE` 与简短的 `PROJECTS` 辅助字样，不再显示容易被理解为残缺的 `S/`。
- 必须出现可感知但克制的动效：首次进入时窗口淡入和轻微上移；项目切换时媒体交叉淡化、身份文字分层进入、强调色平滑过渡；当前项目与工具按钮有柔和呼吸或扫光反馈；信息标签切换保持框体稳定并只对内容做淡入。减少动态效果模式下关闭位移、缩放、呼吸和自动轮播。
- 视觉样式只使用项目自己的图片、视频、文字、CSS 纹理与自有标识，不复制参考启动器的商标或专属图标资产。

## 初始项目内容

初始配置以各项目公开页面能够确认的信息为准：

- ARK：名称使用 `SCHNIE:ARK`，英文代号为 `ARK`，简介使用当前项目已有的公开副标题信息，背景使用现有 HLS 视频。
- BLOG：名称使用 `SCHNIE:BLOG`，英文代号为 `BLOG`，简介使用“第九边缘博客”或站点公开短句“一种新的生命态度”。
- WORLD：名称使用“第九边缘：SCHNIE/生涅”，英文代号为 `WORLD`，简介使用“仅属于虚拟自我的具象世界”。
- ZERO：名称使用 `Zero`，英文代号为 `ZERO`。当前公开页面未提供明确简介，初始配置使用明显的待配置占位文本，不编造项目定位。

按钮文案提供可直接修改的初始值，例如“进入方舟”“阅读博客”“抵达零点”“探索世界”。这些文案不属于固定界面术语，用户可在配置模块中独立替换。

## 配置模型

配置模块导出 `projects`、`tools` 与全局启动器设置。

每个项目包含：

- `id`：稳定项目标识。
- `name`：项目名称。
- `code`：英文代号。
- `description`：一句简介。
- `url`：主按钮打开的目标域名。
- `actionLabel`：项目专属主按钮文案。
- `accent` 与 `accentSoft`：强调色及半透明衍生色。
- `icon`：左侧项目图标或字母标识。
- `media`：`image`、`video` 或 `hls`，以及资源地址、海报图、定位方式。
- `slides`：底部轮播卡片。
- `feeds`：公告、新闻和资讯三个列表。
- `audio`：可选的项目背景音乐。

每个工具包含：

- `id`、`label` 与 `icon`。
- `mode`：`link`、`qr` 或 `both`。
- `href`：可选的直接访问地址。
- `qrImage`：可选的本地二维码图片。
- `description`：工具弹层中的简短说明。

当工具模式为 `both` 时，点击工具图标打开二维码卡片，卡片同时提供“直接访问”按钮。二维码使用本地静态图片，避免把访问地址发送给第三方二维码服务。

## 组件与状态边界

根页面只挂载一个客户端 React 启动器应用，组件职责如下：

- `LauncherApp`：读取配置并持有当前项目、当前资讯标签、当前轮播项、媒体状态与工具弹层状态。
- `DesktopGate`：在支持的桌面视口渲染启动器，在小屏和主要触控小屏设备上渲染访问提示。
- `BackgroundStage`：负责图片、MP4、HLS、海报图与渐变回退。
- `ProjectRail`：负责项目选择和键盘操作。
- `ProjectIdentity`：显示当前项目名称、代号和简介。
- `InformationDock`：组合轮播封面、资讯标签和列表。
- `ToolRail` 与 `ToolPopover`：显示外部工具、二维码和直接访问入口。
- `TopControls`：声音、背景播放和全屏控制。
- `ProjectAction`：显示项目专属按钮文案并打开当前项目 URL。

状态只在 `LauncherApp` 内部流动，子组件通过明确的属性和回调通信。本阶段不新增全局状态库，也不从其他域名实时抓取资讯。

## 媒体行为

- ARK 初始 HLS 视频在静音状态下自动播放，以符合常见浏览器自动播放策略。
- ARK 与 `ark.sch-nie.com` 保持一致，只使用现有 HLS 动画源，不额外生成、保存或加载 MP4 兼容文件。不支持 HLS/Media Source Extensions 的浏览器直接显示海报图，播放控制显示为不可用。
- 媒体初始化区分“加载中”“可播放”和“确定失败”三种状态。支持 HLS 的浏览器在加载期间保持视频元素挂载，仅在 HLS 明确失败后回退海报；不支持 HLS 的环境不尝试创建播放器实例。
- 用户切换项目时暂停离开的媒体，加载目标项目媒体，并更新页面背景、强调色和资讯。
- 声音必须由用户主动开启。声音开关控制当前媒体或项目音频，不尝试绕过浏览器限制。
- 播放按钮只控制当前背景媒体；纯图片项目显示为不可用或隐藏。
- 全屏按钮调用浏览器 Fullscreen API；浏览器拒绝时保持原布局并给出非阻塞提示。

## 异常处理与降级

- HLS 或视频加载失败时先回退到海报图；海报图也失败时显示项目主题渐变。
- 图片加载失败时显示主题渐变和项目代号，不出现破损图片图标。
- 轮播为空时显示项目名称与“内容待配置”；资讯列表为空时显示同尺寸占位行，避免布局塌陷。
- 工具的 `href` 为空或无效时不渲染直接访问按钮；`qrImage` 失败时仍保留链接能力。
- 无可用链接和二维码的工具显示为禁用状态，并提供可理解的提示。
- 用户系统要求减少动态效果时，禁用自动轮播以及大幅缩放和位移动画。
- 小于桌面断点的设备只加载轻量提示页。桌面断点初始设为约 900 像素，并结合主要触控小屏条件，避免平板横屏被不必要地拒绝。

## 可访问性与安全

- 所有项目、工具和控制按钮使用原生按钮或链接，并提供可读的 `aria-label`、键盘焦点样式和提示文本。
- 当前项目、当前资讯标签和播放状态通过语义属性表达。
- 外部链接使用新标签页，并设置 `rel="noopener noreferrer"`。
- 二维码图片具有描述其目标的替代文本。
- 弹层支持 Escape 关闭，焦点不会被隐藏内容截获。
- 不通过 iframe 嵌入外站，不在启动器中请求外站身份信息。

## 验收标准

1. `astro check` 和生产构建通过。
2. `1920x1080`、`1440x900`、`1366x768` 以及较低高度的桌面视口无页面滚动、内容溢出或主要控件遮挡，主窗口保持 24–32 像素安全边距并充分利用视口。
3. ARK 默认选中；支持 HLS/MSE 时 HLS 静音自动播放，切换项目后离开的媒体暂停；不支持 HLS/MSE 时稳定显示海报且不加载 MP4 兜底。
4. 四个项目切换时，背景、项目文字、强调色、轮播、资讯和主按钮文案同步更新。
5. 公告、新闻、资讯标签与轮播均可操作，空数据状态稳定。
6. 每个主按钮在新标签页打开对应项目域名。
7. `link`、`qr` 和 `both` 三类工具均按配置工作；混合工具可扫码，也可直接访问。
8. 声音、背景播放和全屏控制均与当前媒体状态一致。
9. 视频、图片、二维码和空资讯的失败场景具有明确回退。
10. `390x844` 等移动视口只显示桌面访问提示，且不初始化 HLS 或轮播。
11. 键盘可以遍历并操作项目、资讯、工具和主按钮，焦点状态清晰。
12. 浏览器控制台没有由启动器自身产生的未处理错误。
13. 背景图片、海报和视频在所有桌面验收尺寸下覆盖媒体舞台且保持宽高比，可通过项目配置调整视觉焦点。
14. 三个资讯标签在内容数量不同或为空时保持完全相同的外框尺寸和页面位置，超出可见区域的条目不会撑高组件。
15. 右侧工具轨为对齐的图标型竖向轨道；左上角完整显示 `SCHNIE` 品牌字样；项目切换和初次进入具有可见动效，并正确响应减少动态效果设置。

## 不在本次范围内

- 不删除或重写现有博客、文档、角色等旧路由源码。
- 不为其他项目自动抓取、同步或生成资讯。
- 不实现登录、账号、云同步、桌面窗口最小化或关闭功能。
- 不实现移动端启动器布局。
- 不建设后台管理界面；内容维护通过类型化配置文件完成。
